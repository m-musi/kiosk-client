## Mac 更新产物带版本号 + 完整签名（scripts/build.sh）
- 需求：Mac 打包产物文件名带版本号（与 dmg/Windows 一致），便于 latest.json 引用、避免不同版本互相覆盖。
- 发现隐藏问题：Tauri 生成的 `<App>.app.tar.gz` 在 ad-hoc codesign 之前打包，内部 app 只有 linker-signed（`Sealed Resources=none`），更新到别的 Mac 会报"已损坏"。且本机 `bundle_dmg.sh` 挂载检测失败时 tar.gz 根本不生成。
- 方案（build.sh，macOS 分支）：codesign 后**直接从签名后的 .app 新建** tar.gz（不依赖 Tauri 产物），命名为 `<App>_<version>_<arch>.app.tar.gz`（arch: arm64→aarch64），用 `cargo tauri signer sign --app-version <VERSION>` 重新签名生成 `.sig`；构建前清理旧 tar.gz/sig。版本号从 Info.plist 的 CFBundleShortVersionString 读取。
- 验证：签名 trusted comment 含 `file:..._0.1.0_aarch64.app.tar.gz version:0.1.0`；tar.gz 内 app 为完整 ad-hoc 签名（Sealed Resources 正常）。签名校验只针对文件内容、不依赖文件名，重命名安全。
- 更新流程要点（已在对话说明）：latest.json 用 `darwin-aarch64`（M1），url 指向 .app.tar.gz（不是 dmg），signature 填 .sig 全文；顶层 version 必须大于客户端且与实际包一致；客户端须装在 /Applications 才会更新。
- 诊断"其他电脑装昨天包后无自动更新"：服务器 latest.json 已是 0.2.0、含 darwin-aarch64，本机日志显示检测/下载/签名均成功，卡在 install 报 `Read-only file system (os error 30) at .../AppTranslocation/.../tauri_current_app`。根因是用户从 dmg/微信位置直接打开、未拖入 /Applications，macOS Gatekeeper 的 App Translocation 把 app 映射到只读随机目录，Tauri updater 无法写入自身完成替换。解决：首次安装拖进 /Applications，或对已装 app 执行 `xattr -cr`。版本/签名/端点都不是原因。
