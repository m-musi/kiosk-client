- 引导页 800ms 轮询 `check_remote_software`，命中远控黑名单时禁用「进入考试」并提示关闭软件；进入前在 `enter_exam` 中复核。
- 取消启动多屏门禁；进入考试后按显示器列表为非主屏创建整屏 `block.html` 遮挡窗，提示「正在考试中，请在本机屏幕操作」。
- 新增透明置顶 `exam-fab.html` 悬浮退出按钮，点击后打开 `exam-exit-confirm.html` 二次确认（成绩上传且不可更改文案），确认后解除锁定、关闭考试/遮挡/悬浮窗并返回引导页。
- 键盘钩子与守护线程改为受 `lockdown::LOCK_ACTIVE` 控制，仅在考试锁定期间拦截 Alt+Tab/Win/Ctrl+Shift+Esc 等；`deactivate` 停止守护并恢复设置。
- Windows 进入考试时将 HKCU\...\PrecisionTouchPad 的 `ThreeFingerSlideEnabled`、`FourFingerSlideEnabled` 置 0 禁用三/四指切桌面，退出时恢复原值（新增 Cargo 依赖 url、windows-sys 的 Registry feature）。
- 编译校验：`cargo check` 通过（Windows 目标）；macOS 目标未安装，未做交叉编译校验。README 已同步新流程与限制。

## 启动无响应问题排查
- 现象：安装后点击 exe 无窗口；枚举进程发现窗口已创建但全部隐藏、进程无响应。
- 根因：`setup` 中同步执行 `check_for_updates`，更新服务器 `updates.elecbalance.com` 不可达时阻塞主线程，窗口来不及显示。
- 修复：`lockdown::UPDATER_ENABLED = false` 直接跳过检查；检查逻辑改由 `spawn_update_check` 后台线程执行；全局热键注册失败改为非致命。
- 验证：重启后枚举到「山西省电力仿真考试客户端」可见窗口，截图确认引导页正常渲染。
- 另外修复：`AUTO_KILL_COMMUNICATION` 的 `tim`/`qq` 短名会误匹配 `RuntimeBroker.exe` 等系统进程，改为 `tim.exe`/`qq.exe`；引导页轮询加序号防止旧结果覆盖新状态。
- 构建锁报错（failed to remove target/debug/kiosk-client.exe，拒绝访问）是残留 `cargo run`/客户端进程占用产物，非按钮逻辑问题；清理进程后 `cargo check` 通过。

## 「进入考试」按钮无响应根因修复（第二轮验证通过）
- 根因：`enter_exam`/`show_exit_confirm` 是同步 Tauri 命令，同步命令运行在主线程；命令内 `WebviewWindowBuilder::build()` 需派发回主线程事件循环 → 死锁（Tauri v2 Windows 已知问题）。
- 修复：`enter_exam`、`show_exit_confirm` 改为 `async fn` 命令；`show_exit_dialog`（管理员口令窗）热键回调内窗口创建挪到 `std::thread::spawn` 后台线程。
- 验证（真机脚本点击）：exam 日志完整走通 build → overlays → fab → lockdown activated；退出流程 fab→确认→回引导页正常；Tab 键拦截正常。
- 经验：Tauri v2 中凡在主线程上下文（同步命令、快捷键回调、事件循环回调）里创建窗口都会死锁，必须 async 命令或后台线程。
- 注意：AUTO_KILL_COMMUNICATION=true 会杀掉运行中的微信（测试时已发生）。
